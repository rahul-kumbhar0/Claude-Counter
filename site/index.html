01 — Why this exists

Claude's limits are real. The surprise doesn't have to be.

People don't mind a limit. They mind hitting it mid-task with no warning, no idea why, and no way to carry on. Every piece of Wiggleroom exists to remove one of these.

Two windows tick at once. A rolling 5-hour window and a weekly cap (and per-model weekly caps on some plans). Claude's usage page sits behind Settings, so most people only learn about the weekly one when it stops them.→ Wiggleroom shows both, with reset times, right under the message box.
Peak hours burn faster. In March 2026 Anthropic started draining the 5-hour window more aggressively during weekday peak hours, confirmed by an engineer on X rather than an announcement.→ Wiggleroom learns your real cost per message and projects how many you have left.
Long chats cost more every message. Each reply re-sends the whole conversation, project knowledge and uploads. A 150k-token chat can cost 10× a fresh one, and Claude starts forgetting the top.→ A chat-size meter, a nudge at 85%, and one-click Start fresh with a summary.
Deleted chats are gone for good. Anthropic's own export is an all-or-nothing account dump whose download link expires in about 24 hours. There is no per-chat export and no undo.→ Backup any chat, all chats, or Claude Code sessions to a folder or ZIP you keep, incrementally.

02 — Everything it does

Every feature, what it's for, and exactly when you'd use it.

No tiers, no "Pro only" badges. Each card says what the feature does, when it earns its keep, and where to find it.

Measure

⏱

5-hour window meter

Percent used of the rolling 5-hour window plus the exact reset time, read from Claude's own usage data.

Use it when: you're pacing a work session and want to know if the next big prompt fits before the reset.
Always visible in the bar · updates every minute and after each message.
📅

Weekly cap meter

The limit that actually ends longer projects, with its reset day and time. Per-model weekly caps (Opus, Sonnet) appear when your plan reports them.

Use it when: deciding whether to spend Opus on a routine task or save it for the hard part of the week.
In the bar · details panel · toolbar popup.
📏

This-chat size meter

An estimate of what this conversation re-sends with every message: chat text, project knowledge and uploads, against the 200k context window.

Use it when: replies get slower and Claude starts "forgetting" things. Past 85% you get a nudge to start fresh.
Click it for the breakdown by source.
🎯

Messages left learns

How many more messages like your recent ones fit in the current window. Starts from a documented baseline, then learns your real cost per message by watching how much each send actually moved the meter.

Use it when: you have 8 things to ask and want to know if they fit before the reset.
Model-aware: Opus ≈ 5× Sonnet. Shows "learned" once it has samples.
📈

Weekly pace projection new

From your own usage history: burn per day, the day you'd hit the weekly cap, and whether that lands before or after the reset, so you know if you have room to spare.

Use it when: Monday afternoon, deciding how hard you can push the rest of the week.
Details panel and popup, with a 7-day sparkline.
🔔

Alerts & reset notifications

In-page warnings at 80% and 95% (yours to change), a heads-up when a limit is reached, and a desktop notification the moment a window resets.

Use it when: you step away and want to come back exactly when the room is back.
Settings tab · one alert per level per window, never nagging.

Toolbar badge & popup

The extension icon shows your 5-hour (or weekly) percent from any tab. The popup has both meters, pace, resets and quick actions, no Claude tab needed.

Use it when: you're in your editor and wonder whether it's worth opening Claude right now.
Badge colour: green → amber → red.

"Why am I limited?"

A plain-English explainer of the two windows, peak-hour throttling, and why long chats drain faster, next to the numbers for your own chat.

Details tab in the ⋯ panel.

03 — How it works

Nothing to configure. It's just there.

01

Install

Download the ZIP, load it in Chrome, Edge, Brave or Arc. No sign-up, no API keys.

02

Open Claude

The bar docks under the message box and reads the same usage data Claude's own settings page shows.

03

Work

It watches each message to learn your real cost, warns you at 80% and 95%, and nudges you when a chat gets heavy.

04

Keep & carry

Back up with one click, start fresh when a chat is heavy, carry elsewhere when you're out of room.

Under the hood: a content script reads Claude's usage endpoint with your existing login, observes (never alters) the page's own requests to learn per-message cost, and renders in a Shadow DOM so it can't break Claude's UI. Backups are written with the File System Access API or a ZIP built in the browser.

05 — Privacy

Your chats never leave your computer.

What it does

  • Reads your own usage and chats inside your browser, with the login you already have
  • Observes the page's own requests to learn cost per message, and never changes them
  • Writes backups only to the folder you pick, or a ZIP you download
  • Keeps settings, usage history and prompts in the extension's local storage
  • When you carry to another AI, it types text into that site's box and downloads a file, you decide what to send

What it never does

  • Never sends your chats, files, keys or usage to any server
  • Never sends messages to Claude on your behalf
  • Never shows ads, sells data or phones home
  • Never needs an account, API key or extra login
  • Never touches sites other than claude.ai and the AI you explicitly carry to

06 — Install

Up and running in two minutes.

Load the extension

  1. ⬇ Download wiggleroom-extension.zip and unzip it.
  2. Open chrome://extensions (Edge: edge://extensions).
  3. Turn on Developer mode (top-right).
  4. Click Load unpacked and pick the unzipped folder.
  5. Open claude.ai. The bar appears under the message box.

Chrome, Edge, Brave, Arc, Opera (Chromium 116+). Chrome Web Store listing: in review.

First five minutes

  1. Send one message. Watch the 5-hour meter move, that's a learned sample.
  2. Click any number for the details panel: breakdown, pace, resets.
  3. Open a long chat and try ✦ Start fresh, review the summary before sending.
  4. ⋯ → Backup → Export this chat, open conversation.html.
  5. Save a prompt, type // in the box.

Tip: pick a backup folder inside OneDrive, iCloud or Google Drive to get cloud sync for free.

07 — FAQ

Common questions.

Is everything really free?
Yes. Every feature on this page, with no quotas and no account. There is no Pro tier. If the project ever needs support to keep going, that will be optional, never a wall in front of a feature.
How accurate are the meters?
The 5-hour and weekly percentages and reset times come from Claude's own usage endpoint, the same data as Settings → Usage, so they're as accurate as Claude's. The chat-size figure and "messages left" are estimates and are marked with ~. Messages-left starts from a documented baseline and switches to a learned figure once it has watched a couple of your own messages.
How does "messages left" learn?
Each time you send a message, Wiggleroom notes the meter before and after, and the size of the chat and the model used. It keeps the median cost per 1k tokens of context, so a long Opus chat and a short Sonnet chat each get their own realistic number.
How does "Start fresh" save usage?
Every message re-sends the whole chat. A fresh chat that starts with a 2–4k-token summary instead of a 150k-token history costs a fraction per message and gives Claude a cleaner context. You always review the summary before sending it.
What if Claude changes its website or API?
The usage parser is tolerant: it looks for any usage-shaped data in what the page already receives, not one fixed field name. The bar renders in its own Shadow DOM and positions itself relative to the message box, so layout changes rarely break it. When something does, an update follows.
Does it work with Claude Code?
Yes. The bar runs on claude.ai/code and can back up web sessions; the local exporter page reads the .jsonl transcripts from Claude Code on your machine (terminal, desktop app, VS Code, JetBrains).
Will it interfere with Claude or get me in trouble?
It never sends messages, never modifies requests and only reads data your browser already has as a logged-in user, the same as opening the usage page yourself. It's a read-and-render tool.
Is this made by Anthropic?
No. Wiggleroom is independent and not affiliated with or endorsed by Anthropic.
